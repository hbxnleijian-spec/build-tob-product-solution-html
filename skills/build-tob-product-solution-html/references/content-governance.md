# 内容治理规范

## 目录

1. 证据状态
2. 领导审议表达
3. AI 与确定性控制
4. 示例与占位规则
5. 验收措辞

## 1. 证据状态

重要内容必须同时使用 `data-semantic` 值和可见文字标签：

| 取值 | 含义 | 编写规则 |
|---|---|---|
| `confirmed` | 已验证的当前事实 | 条件允许时标注来源、日期或证据 |
| `requirement` | 来自已识别来源的要求 | 不得描述为已经实现 |
| `inference` | 基于材料形成的合理解释 | 明确标识为分析或推断 |
| `recommendation` | 拟议方向 | 标明决策责任人或下一项决策 |
| `target` | 规划结果或门槛 | 不得描述为已经达成 |
| `tbd` | 未知或待确认事项 | 说明需要确认什么以及由谁确认 |
| `risk` | 可能产生不利影响的条件 | 视情况说明影响、应对、触发条件和恢复方式 |

来源冲突时，必须展示冲突及其影响，不得静默选择便于编写的版本。

## 2. 领导审议表达

- 优先给出决策、边界或管理影响。
- 区分当前事实、存在问题、建议动作、预期价值和决策请求。
- 组织、系统、版本和日期必须使用正式来源中的准确名称。
- 除非有充分证据，不得使用“全面”“已经”“完成”“保证”等绝对化表述。
- 技术实现细节应服务于业务价值、责任、控制和验收，不得喧宾夺主。

## 3. AI 与确定性控制

- 说明为什么需要 AI，以及规则、搜索或传统自动化为何不足以单独解决问题。
- 金额、比例、日期、权限、流程状态、阈值和正式指标必须由规则或程序计算。
- 审批、风险接受、正式发布、签署、责任分配和正式记录修改必须由授权人员完成。
- 模型或工具失败必须可见；重要流程必须具备重试、降级、人工接管、回滚和失败证据保留机制。
- 视场景覆盖数据隐私、租户隔离、知识权限、提示注入防护、敏感信息处理和审计要求。

## 4. 示例与占位规则

- 人工构造的内容必须以“示例”开头，并使用“某集团”“业务系统 A”等中性实体。
- 未知值使用“待确认”。不得编造日期、组织、预算、KPI、基线或已实现成效。
- 组件展廊只用于展示布局，不构成真实项目已经具备相关能力的证据。

## 5. 验收措辞

可量化验收应按照“条件 + 操作 + 可观察预期结果 + 证据”编写。必须区分规划门槛和已经执行的测试结果；未执行的检查应标识为未执行，不得标识为通过。
