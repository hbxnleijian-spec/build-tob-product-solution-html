## 1. 选择顺序

先确定文档框架，再根据每类信息关系选择一个主要组件：

1. 叙述：正文、导语、结论、提示或边界声明。
2. 并列：卡片网格或指标卡。
3. 重复字段：表格或矩阵。
4. 时间：时间线、路线图或甘特图。
5. 顺序：步骤流、生命周期或阶段流。
6. 责任：角色卡、泳道、RACI 或人机责任边界。
7. 决策：方案选项、推荐结论、决策矩阵、红线、风险、假设或依赖。
8. 证据：图形、来源注释、追溯表、验收指标、术语表或版本记录。

优先选择能够保留信息关系的最小组件。不得仅为视觉装饰而把连续长文拆成大量卡片。

## 2. 组件族

| 组件族 | 适用条件 | 禁用条件 |
|---|---|---|
| 文档框架 | 输出为长篇独立 HTML | 用户需要应用界面或数据看板 |
| 导语与提示 | 需要突出一个结论或边界 | 需要比较多个同层级事项 |
| 卡片网格 | 2–8 个并列概念具有共同字段结构 | 内容具有严格顺序或高密度表格关系 |
| 指标卡 | 基线、现状、目标、单位和状态均已明确 | 指标仅为建议且统计口径尚未批准 |
| 比较与决策 | 方案选项或前后状态可按共同标准比较 | 各事项无法使用共同标准评价 |
| 时间线与路线图 | 日历顺序或分期交付是重点 | 需要精确工期和依赖关系，应改用甘特图 |
| 步骤流与生命周期 | 有序动作或治理状态是重点 | 多角色并行开展活动，应改用泳道 |
| 泳道与 RACI | 需要表达责任、交接或问责 | 只需说明先后顺序，不涉及责任 |
| 架构与能力 | 需要表达层次、领域、系统或数据流 | 已有权威截图足以说明关系 |
| 风险、假设与依赖 | 不确定性会影响决策或交付 | 已经成为有明确责任人的确定问题 |
| 成本与收益 | 范围包含财务结构或价值逻辑 | 金额未知，应显示待确认而不是编造 |
| 追溯与验收 | 需求必须映射到交付内容和验收证据 | 文档仍处于早期愿景阶段且尚无验收范围 |

## 3. 常用组合

### 领导审议稿

封面 → 决策边界摘要 → 决策要点 → 现状 → 方案比较 → 推荐结论 → 路线图 → 风险 → 待决事项。

### 产品建设方案

封面 → 范围 → 需求 → 能力地图 → 分层架构 → 场景或流程 → 系统职责 → 分期路线图 → 投资 → 验收 → 风险与依赖。

### AI 赋能企业方案

补充 AI、规则、人员和主责系统的明确分工，以及确定性控制边界、证据追溯、失败可见、降级和恢复机制。

### 既有 HTML 视觉改造

盘点内容与锚点 → 映射历史类名 → 仅替换布局 → 比较改造前后文本 → 验证响应式和打印结果。未经授权不得补写缺失的业务内容。

## 4. 密度与打印规则

- 桌面端阅读量较大的卡片最多使用 4 列；5–8 列仅用于短标签或紧凑步骤。
- 宽度低于 960 像素时收敛为 2 列，低于 640 像素时收敛为 1 列；可横向滚动的表格除外。
- 打印时避免拆分卡片、图形、提示块和短表格。
- 打印表格必须重复表头，并确保第一识别列具有明确含义。
- 仅在篇章或章节边界设置强制分页，不得让每个小节都另起一页。
